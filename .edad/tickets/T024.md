## Context

`preflight` (`edad/session.py`) checks the host's toolchain against
`requirements-gate.txt` through `gate_toolchain_problems`, then hands the docker tier
to `validate_network`, which probes the agent image for egress, proxy refusal and
proxy permission — never for versions. `Dockerfile.agent` bakes the pins in at build
time, so the image only follows a pin bump when someone rebuilds it. After any bump a
stale image runs the agent under old tools while the host gate judges under new
ones, and nothing says so. The pytest 8.4.2 → 9.0.3 bump (Dependabot PR #1) is the
first time this matters; the guard lands before it.

`validate_network`'s probe sequence is pinned by T016's frozen
`tests/test_session_network.py::test_an_internal_network_is_accepted`, so the new
probe is a sibling called *after* it, not a step inside it. The queue calls
`validate_network` once at plan time from `session_queue.prepare_tier` and turns
`Abort` into its own `Refusal`; the session calls it from `preflight`. Both call
sites get the image check, or a stale image costs a night before `no_progress` fires.

**The stubs.** The tree already contains a `REBUILD_IMAGE_CMD` with the wrong value,
a `validate_image` that asks an image named nothing about nothing and refuses
nothing, a `preflight` that calls it on every tier, and a `prepare_tier` that takes
`root` and does nothing with it. They exist so the frozen tests fail by asserting.
Replace them; do not build on them.

**Why nothing-pinned must mean no probe.** `tests/test_session_queue.py` (frozen for
a dozen done tickets) drives docker nights through `run_queue` with only
`validate_network` faked, from a fixture repo with no `requirements-gate.txt`. A
guard that always probes runs a real `docker run` from inside those tests, and fails
four of them wherever docker is absent — including inside your container, where your
own `full_gate` runs. The host check compares nothing when nothing is pinned; this
check does the same. Measured at `/to-spec`, not reasoned.

**Your container has no docker and no git.** `probe_container` returns `None` there,
so nothing in the frozen suite may reach a real probe once you are done: the docker
tier is faked at the `session` module in every test that touches it. If a
`test_session_queue.py` test fails for you naming a container or a network, the
guard is probing when it should not — that is the defect, not the test.

## Goal

A docker-tier run refuses to start unless the agent image carries exactly the
versions `requirements-gate.txt` pins, from the session's preflight and from the
queue's plan-time tier preparation alike, on `--dry-run` too, naming each mismatch
and the rebuild command. The default tier never asks. The procedure for bumping a pin
is in QUICKSTART, in the order the guard forces, quoting the same rebuild command the
refusal prints.

## Required interface

In `edad/session.py`:

- `REBUILD_IMAGE_CMD: str` — a module constant. Starts with `docker build`, names
  `Dockerfile.agent` and `edad-agent:latest`. The refusal quotes it verbatim; so does
  QUICKSTART.
- `validate_image(image: str, root: Path, network: str | None) -> None`.
  - Reads the checkout's pins with `_pinned_versions(root)` from `edad.gate` (the
    same list the host was just checked against). **No pins — no file, or no `==`
    line — return without probing.**
  - Otherwise exactly one `probe_container(network, image, script)` call, on the
    named network. The script must name every pinned name (the test checks each as a
    substring) and print one `<name>==<version>` line per pinned name, using
    `importlib.metadata.version`. That output shape is the contract the frozen
    fake speaks.
  - `probe_container` returning `None`, or a non-zero exit, raises `Abort` whose
    message names the image and does not contain the word `pinned` (it is not a
    mismatch, so no pin is blamed).
  - Any value not equal to its pin raises `Abort` containing
    `image <image> does not match requirements-gate.txt`, one
    `<name> <found>, pinned <want>` per mismatch, no mention of names that match,
    and `REBUILD_IMAGE_CMD`. Prose around those substrings is yours.
- `preflight(...)`: after `validate_network` returns, and only when `sandbox ==
  "docker"`, call `validate_image(image, root, network)`; return what
  `validate_network` returned. On `--dry-run` the image probe still runs (the
  network validation has already stopped after its egress check by then, so the
  observed order is `internal, egress, image`). On sandbox `none` the probe is never
  called, pins or no pins.

In `edad/session_queue.py`:

- `prepare_tier(sandbox: str, network: str | None, root: Path) -> bool` — `root` is
  required (the stub already has the signature; `run_queue` already passes it).
  After `validate_network(sandbox, network)`, call
  `validate_image(DEFAULT_IMAGE, root, network)` inside the same `try`, so its
  `Abort` becomes the queue's `Refusal` and a proxy this run created is removed on
  the way out, exactly as for a network refusal. The queue has no `--image` flag;
  the default image is the one it checks. A `none` night still asks nothing.

In `QUICKSTART.md`:

- A `## Bumping a gate pin` section (H2, that exact heading), placed anywhere. It
  must contain `pip install -r requirements-gate.txt`, then `--dry-run`, then
  `REBUILD_IMAGE_CMD` verbatim, then `--dry-run` again — in that order of first
  occurrence (the last `--dry-run` in the section must come after the rebuild
  command). The order it documents: merge the pin PR → install the pins on the host
  → approve the next ticket → dry-run a night and expect the image refusal → rebuild
  the image → dry-run again and expect none → run that night for real. Say why the
  order is what it is: until the pin PR is merged the host toolchain check refuses
  first, so the image refusal is only reachable after the merge.
- In that section, after `REBUILD_IMAGE_CMD` and before the last `--dry-run`, the
  text must contain `--image` and a form of "rebuild" (the test matches
  `rebuil[dt]`): the docker tier runs the agent in an image built on top of
  `edad-agent:latest` with the target's test dependencies layered on (QUICKSTART's
  docker-tier paragraph already says so, and that `--image` names it), and that
  image keeps the old pin until it is rebuilt in turn. Say that rebuilding the base
  alone brings the same refusal back. The constant does not change (D11).
- The dry-run commands in that section are `python3 -m edad.session run T00N
  --sandbox docker --network <name> --dry-run`. Only `edad.session run` has
  `--dry-run`; the queue does not, and the test refuses the string `session_queue`
  anywhere in the section. Every `--dry-run` must be on a line that also contains
  `edad.session run` (D12).
