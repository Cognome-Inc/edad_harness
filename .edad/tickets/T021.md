## Context

`die()` in `edad/gate.py` prints `edad: <msg>` to stderr and raises a bare
`SystemExit(2)`. `run_session` in `edad/session.py` wraps its iteration loop and full
gate in `try` / `except Abort` / `finally`, and the `finally` writes the session log.
T020 put the first refusal an agent's own edits can trigger inside that loop:
`evaluate()` now measures the toolchain at the worktree and dies on a mismatch before
a `Record` exists. `preflight` measures at the repo root, so the only way the two
disagree is the agent editing `requirements-gate.txt` — in scope (the queued pytest
bump) or out of it (a stray; scope is checked inside `evaluate` *after* the toolchain,
so the stray is never recorded as the kill it is). Either way the `SystemExit` escapes
`run_session`, the log is written with the dataclass default `outcome: "incomplete"`
and `abort_reason: null`, and no `ABORTED ... left at <wt>` line is printed. The proxy
is still removed and the worktree is left; only the paper trail is wrong.

The refusal must stay a `SystemExit`: T020's frozen
`test_evaluate_refuses_a_toolchain_mismatch_before_running_anything` asserts
`SystemExit` with `code == 2` and the message on stderr, and every other
`pytest.raises(SystemExit)` in the suite pins the same at the CLI. `gate.main()` and
`session.main()` are not touched.

The stub is in place: `class Refusal(SystemExit)` exists in `edad/gate.py` directly
above `die()`, with a stub docstring to replace, and `die()` still raises the bare
`SystemExit(2)`. So D1's test fails on its `isinstance` assertion rather than on an
`AttributeError`, and D2's two tests fail on `'incomplete' == 'aborted'` because the
exit escapes the session and the driver catches it.

The frozen test does not shell to git: every side effect of `run_session` is replaced
on the `session` module, and the real `evaluate` is steered through `measure_toolchain`
faked on the `gate` module, the way T020's tests do. `tests/test_session_queue.py` does
shell to git and fails under `--sandbox docker` for the agent, not for the verifier;
that failure is an environment artifact and not to be worked around.

## Goal

A refusal names itself. Any `die()` raises a `Refusal` that is a `SystemExit(2)` whose
`str()` is the reason — nothing at the CLI moves. `run_session` catches it beside
`Abort`, so a gate refusal reached at the acceptance gate or the full gate ends the
session the way any other stop does: `outcome: "aborted"`, `abort_reason` the
refusal's message, the ABORTED line naming the worktree, return 1. Iterations that
ran before the refusal stay in the log.

## Required interface

Pinned by `tests/test_gate_refusal.py`; read it first. Names are exact.

**`edad/gate.py`**

- `Refusal(SystemExit)` — replace the stub. `__init__(self, reason: str)` calls
  `SystemExit.__init__(self, 2)` and stores the reason; `__str__` returns it. The
  test asserts `isinstance(exc.value, gate.Refusal)`, `exc.value.code == 2`, and
  `str(exc.value)` equal to the message passed to `die`. Nothing else on the class.
- `die(msg)` — print `edad: {msg}` to stderr exactly as today, then `raise
  Refusal(msg)`. Every other site is unchanged; this is the one edit.

**`edad/session.py`**

- Import `Refusal` from `.gate` in the existing import block.
- The handler in `run_session` becomes `except (Abort, Refusal) as e:` — the
  `Unwinnable` isinstance and the `log.outcome` / `log.abort_reason` / ABORTED print
  are unchanged. `str(e)` is the reason because `Refusal.__str__` makes it so. No new
  outcome string; `PROMOTED_OUTCOMES` is untouched, so the session returns 1.
- Do not wrap individual `evaluate` calls: the test with a mismatch only at the full
  gate expects the same log shape, and the boundary is what catches the next `die()`
  site that lands in the loop.
- `die()` prints before raising and the boundary prints ABORTED after, so an
  in-session refusal appears twice on stderr, in two voices. Accepted; do not
  suppress either.
