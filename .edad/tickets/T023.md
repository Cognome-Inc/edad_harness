## Context

`run_session` (`edad/session.py`, the iteration loop) runs the agent, commits its
work with `commit_iteration`, then calls `evaluate`. The `log.iterations.append(...)`
comes after `evaluate` returns. When `evaluate` raises `Refusal` — the toolchain check
at the top of `evaluate`, which runs before the `Record` exists — the session's
`except (Abort, Refusal)` records the outcome and reason and the log is written with
`iterations: []`. The agent ran, its commit is on the branch, and the log says no
iteration happened.

`session_queue.no_commit_abort` reads `iterations[].made_commit` and nothing else; an
empty list is "no iteration made a commit", the counter rises, and two such nights
fire the `no_progress` breaker with the reason "the agent is not running". Reproduced
at `60def98` through T021's `Night` fixture: `outcome: aborted`, `iterations: []`,
`no_commit_abort → True`, `breaker_fired(no_commit_aborts=2) → "no_progress"`.

T021's spec deferred this ("logging the agent tail on a refused iteration needs an
`Iteration` without a verdict, which is a shape nothing reads yet",
`.edad/specs/gate-refusal.md:100-103`). The queue consequence was not seen then. The
pytest 9.0.3 bump is the first ticket whose agent edits `requirements-gate.txt` by
design, so its night produces exactly this log; this ticket lands first.

The same refusal ends "Install the pins: pip install -r requirements-gate.txt". In a
worktree that file may be the one the agent just wrote, possibly outside the ticket's
scope, and because the refusal precedes `changed_files` and `check_scope` nothing
records that. The ordering is deliberate (a wrong toolchain makes every later verdict
meaningless) and is not changed; the wording is, and only where the gate is judging a
worktree.

**Frozen fixtures that reach the change.** `tests/test_gate_refusal.py`'s `Night`
runs the real `run_session` and `evaluate`; `changed_files` is faked to `[]` there, so
T021's two D2 tests stay on the unchanged wording. `tests/test_gate_trusted_inputs.py`
fakes a matching toolchain and never reaches the refusal. Both were probed against a
throwaway implementation before approval: 259 passed, ruff clean, no fixture
amendment needed.

**Lint.** Adding a `try/except` to `run_session` takes it over ruff's `PLR0912`
branch limit. `run_session` already carries `# noqa: PLR0915` for the same reason
(a linear driver; splitting it hides the flow); extending that comment to
`# noqa: PLR0912, PLR0915` is the intended fix, not a restructuring.

**Git in the container.** No test in the frozen file shells to git. Elsewhere in the
suite `tests/test_session_queue.py`, `tests/test_gate_mutation.py` and
`tests/test_gate_trusted_inputs.py` do, and fail for the agent under `--sandbox docker`
while passing for the verifier on the host — an environment artifact, not the agent's
to work around.

One test in the frozen file is green at base and is not in `acceptance`:
`test_a_refusal_with_the_pins_unchanged_keeps_the_install_advice` (D6). It guards the
wording change against over-reaching — a worktree that changed other files but not
the pins still gets the install advice, verbatim. `full_gate` runs it. Keep it green.

## Goal

A session whose acceptance gate refuses still stops on that first refusal, but the
refused iteration is in the session log first: the agent's exit and commit, whether
it committed, the gate not passed, a `refusal:`-prefixed signature, the refusal as
its violation, and the agent's output tail. The queue therefore reads a
refused-but-committed night as the agent running. When `evaluate` has a `base_ref`
and `requirements-gate.txt` is among the files changed since it, the refusal says the
worktree changed the pins and whether that file is in scope, and does not advise
installing them; with no `base_ref`, or with the pins unchanged, the wording is what
it is today.

## Required interface

Pinned by `tests/test_refused_iteration.py`; read it and the `Night` fixture in
`tests/test_gate_refusal.py` first. Substrings are exact.

**`edad/session.py`** — inside the iteration loop of `run_session`:

- Wrap `rec = evaluate(wt, ticket, "acceptance", base)` in `try/except Refusal as e`.
  On refusal, append
  `Iteration(n, exit_code, commit, False, f"refusal:{e}", [str(e)], made_commit, out[-AGENT_TAIL:])`
  to `log.iterations` and re-raise. Nothing after the append runs for that iteration:
  no `write_record`, no `check_kills`, no `retry_prompt`. The existing
  `except (Abort, Refusal)` handler is unchanged and still produces `outcome: aborted`
  with `abort_reason = str(e)`. `Refusal` is already imported from `.gate`.
- The test asserts, on the log: exactly one iteration; `gate_passed is False`;
  `signature.startswith("refusal:")` and the refusal's frozen prefix inside it;
  `violations == [abort_reason]`; `made_commit is True` under `Night` (its fake
  `commit_iteration` returns a new SHA); `commit == "b" * 40`; `agent_exit == 0`;
  `agent_output == "bumped the pin"`; and that `<root>/.edad/records` does not exist.
  It also asserts `measure_toolchain` was called once — a refusal is not retried.
- `Iteration`, `SessionLog`, `check_kills`, `failure_signature` and
  `edad/session_queue.py` are not changed.

**`edad/gate.py`** — `evaluate` and `die_on_toolchain_mismatch`:

- `die_on_toolchain_mismatch` gains keyword-only arguments with defaults so
  `cmd_approve`'s call `die_on_toolchain_mismatch(toolchain_problems(measurements))`
  and `tests/test_harness_identity.py`'s expectations are untouched. With the defaults
  the message is byte-for-byte what it is today, "Install the pins: pip install -r
  requirements-gate.txt" included.
- In `evaluate`, when `toolchain_problems(measurements)` is non-empty AND `base_ref`
  is not `None`, call `changed_files(root, base_ref)`; if `"requirements-gate.txt"` is
  in it, compute its scope verdict with `check_scope(ticket, ["requirements-gate.txt"])`
  and refuse with a message that keeps the frozen prefix
  `the gate's toolchain does not match requirements-gate.txt: <problems>` (the check's
  own problem line, e.g. `pytest: 9.0.3, pinned 8.4.2`, must survive), contains
  `worktree changed requirements-gate.txt`, contains either `in scope` (and not
  `out of scope`) or the stray in `check_scope`'s own wording
  `out of scope: requirements-gate.txt`, and does not contain `pip install`.
  Otherwise refuse as today. When `base_ref` is `None`, `changed_files` must not be
  called: `tests/test_harness_identity.py` calls `evaluate(tmp_path, TICKET)` in a
  directory that is not a git repository.
- The session preflight's own copy of the install advice (`edad/session.py`,
  `preflight`) judges the operator's checkout and is not changed.
