## Context

Seam S7 is a pure writer: a night's results go in and Markdown comes out. Its
layout is the grill's, under D20:

```
# Night <date> - run branch <branch>
## Needs you            (panel skipped; failed tickets; unfixed majors)
## Test strength        (mutation score per ticket, survivors)
## Dismissed findings   (with reasons)
## Fixed overnight
## Nits                 (grouped by ticket)
```

The panel tickets (T033–T035) drive this writer from their own tests. That is
why each of them is blocked by this ticket.

### Required interface

`edad/review.py` has a stub that returns `""`. Replace it:

```python
def morning_notes(date: str, run_branch: str, sessions: list[dict]) -> str
```

It is pure: it returns the page, and spawns and writes nothing. `sessions` are
the night's session logs, which is what the queue reads (T037). Each has
`ticket`, `outcome` and `abort_reason` as today, and a `panel` that T036 adds, or
`None` when the session ended before the panel ran:

```python
panel = {
    "skipped": bool,                 # --skip-review-panel (D13)
    "unfixed": [finding, ...],       # confirmed, still open after the fix rounds (D4)
    "fixed": [finding, ...],         # confirmed and fixed overnight
    "dismissed": [finding, ...],     # refuted by the disprover, each with a "reason" (D10)
    "nits": [finding, ...],
    "mutation_score": {"killed": int, "total": int, "survivors": [str, ...]} | None,  # D3
}
finding = {"item": "C3", "severity": "major", "issue": "..."}
```

`finding` uses the fields the test reviewer already emits (`parse_findings`).
This shape is a contract for T033–T037: the panel and mutation-score runs must
produce it, and the session log must carry it.

What the tests pin:

- The first line is exactly `# Night <date> - run branch <run_branch>`.
- The `## ` headings are exactly the five above, in that order, even on an empty
  night.
- Each finding's `issue` (and each dismissal's `reason`) appears in its own
  section and in no other.
- "Needs you" has, in this order: a line naming each skipped ticket with the word
  `skipped`; a line per failed ticket (any `outcome` other than `passed`) naming
  the ticket and its outcome, with its `abort_reason` in the section; a line per
  unfixed finding naming the ticket and the issue. A ticket with nothing open is
  not mentioned there.
- "Test strength" has a line naming each ticket with its score as
  `killed/total`, and every survivor in the section.
- A dismissal's issue and reason are on one line. A fixed finding's line names
  its ticket.
- Under "Nits", each ticket's nits come after a line naming that ticket and
  before the next ticket's.
