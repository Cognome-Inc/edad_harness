## Context

Today `gate approve` locks whatever frozen tests it is given, as long as they go
red. The only thing standing behind "these tests are any good" is a human reading
them, and that reading is the bottleneck on a night of tickets. The review-loops
spec moves the human to *what* a ticket must do (its acceptance, decisions, scope
and full gate) and hands the test lines to a fresh reviewer (T030, T031).

This ticket is the gate's half: the judge learns to refuse. It adds no model
calls; everything that launches a reviewer lives in `edad/review.py`, never here
(D17).

**Two decisions are narrowed by later ones. The later one wins.**

- D12's line says "criteria and decision list". D26 narrows that to a sha256
  over `acceptance`, `decisions`, `scope` and `full_gate`, and nothing else in
  the ticket.
- D25 says the five stand-ins each gain one line. Three of the five
  (`tests/test_harness_identity.py:307`, `:457`, `:546`) get their fakes from
  the one helper `approve_fakes` (`tests/test_harness_identity.py:136`), so the
  fake is added there once. The other two are added just above
  `tests/test_gate_red_proof.py:336` and `tests/test_gate_mutation.py:524`.
  The line is `monkeypatch.setattr(gate, "review_problems", lambda root, tkt:
  [])`. This amendment was made **before approval** and changes nothing those
  tests assert. It makes the locks of the earlier tickets that froze those files
  stale. The grill accepted that, since nothing re-checks a done ticket's lock.

**The night's re-approval.** The queue re-approves each ticket on the run branch
by spawning `python3 -m edad.gate approve <T>` (`reapprove`,
`edad/session_queue.py:479`). The review check therefore runs there with no
queue change, as long as the review, criteria and override records are
committed on main. See `## Widened scope`.

## Goal

`approve` refuses unless both of these hold:

- a passing test-review record, or an override, matches the current frozen
  file bytes;
- the ticket's criteria fingerprint still matches the one a human approved.

Two new subcommands write those human records. Both work only from a real
terminal and record `git config user.email`. Neither takes a typed name.

- `approve-criteria <T...>` writes `.edad/hashes/<T>.criteria.json` for each
  ticket.
- `override-review <T> --reason "..."` writes `.edad/hashes/<T>.override.json`,
  tied to the current frozen bytes.

## Required interface

`edad/gate.py` lands with returning stubs and the parser entries already in
place. Each frozen test goes red on its assertion. Replace the bodies; keep the
names, signatures and parser.

- `review_problems(root: Path, ticket: dict) -> list[str]` returns `[]` when
  approve may proceed and one line per reason otherwise. **Both** checks live
  here, the review and the criteria. The older stand-ins fake exactly this one
  name, so a second check outside it would refuse them.
  `cmd_approve` calls it by module name once the frozen files are known to
  exist, before any command runs, and refuses through `die()` when it reports
  anything. A refusal over the review says "review", and one over the criteria
  says "criteria"; the tests look for those words.
- **Criteria record** `.edad/hashes/<T>.criteria.json`:
  `{"sha256": <64 hex>, "approved_by": <git email>, "approved_at": <ISO time
  with timezone>}`. The sha256 covers `acceptance`, `decisions`, `scope` and
  `full_gate` and nothing else in the ticket (D26), in a canonical
  serialisation (for instance `json.dumps(..., sort_keys=True)` of those four
  keys). It is stale when it no longer matches the ticket as it is now.
- **Review record** `.edad/hashes/<T>.review.json` is written by T031 and only
  read here, in this shape:

  ```
  {"rounds": [{"round": 1, "verdict": "pass" | "fail", "model": "...",
               "frozen": {"<frozen path>": "<sha256>"}, "findings": [...]}]}
  ```

  A review counts when **any** round has `verdict == "pass"` and its `frozen`
  equals `{path: sha256}` of the ticket's frozen files as they are now.
- **Override record** `.edad/hashes/<T>.override.json`:
  `{"approved_by": <git email>, "reason": <text>, "approved_at": <ISO time
  with timezone>, "frozen": {path: sha256}}`. It stands in for a passing review
  while `frozen` equals the files as they are now. It does not stand in for the
  criteria.
- **`approve-criteria <T...>`** (one or more tickets) writes one criteria record
  per ticket. **`override-review <T> --reason "..."`** writes the override.
  Both refuse through `die()`, with a message that says "terminal", unless
  `sys.stdin.isatty()` is true. The tests replace `sys.stdin`, so read it
  there, not through `os.isatty(0)`. Both record `git config user.email` as the
  approver and take no typed name. Refuse when the email is unset.
- A missing or unreadable record counts as no record. It is never an error.

**Git in the container.** These tests run real `git config user.email`
against a config file they write and point `GIT_CONFIG_GLOBAL` at. That works
inside the agent container, measured on `edad-agent:latest`, because the
tests run outside any repository. The suite's other git-dependent test,
`test_run_log_is_gitignored_telemetry`, still fails in the container and
passes on the host. That one is not yours.

## Widened scope

- `edad/session_queue.py` is in scope because the spec's D2 names it, for the
  night's re-approval. `reapprove` already spawns `edad.gate approve`, so the
  review check should reach the night with no queue edit. Touch the queue only
  if a frozen test shows it does not.

## Out of scope

- Writing review records, which is T031. Launching any reviewer, which is
  T030 and T031.
- Exempting locks made before this feature (rejected under D25).
- Protecting against an operator who fakes a terminal (a known limit under
  D22).
