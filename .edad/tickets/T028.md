## Context

The review-loops spec adds a review panel that runs after the gate passes. Two
of its verdicts come from tools rather than from a model: bandit (a Python
security scanner, run offline) and mutmut (which measures the *mutation score* —
how many deliberately broken copies of the changed code the frozen tests catch).
Both verdicts must belong to the commit, the rule pytest, ruff and PyYAML
already follow, so both tools become gate pins.

Today `requirements-gate.txt` pins pytest, ruff and PyYAML only, and
`VERSION_PROBES` in `edad/gate.py` probes the PATH copy of pytest and ruff only.
Everything downstream is already generic: `measure_toolchain` measures every
`==` line in file order, every record's and lock's `toolchain` block is built
from that measurement, approve refuses a host that does not match, and the
docker tier's image check (`validate_image`) compares the agent image against
the same list. Adding the two pins is most of the work; the probe entries are
the rest.

This is the first ticket of nine from `.edad/specs/review-loops.md`
(T028–T036). It is the smallest and has no dependencies.

**Before this ticket's night, the operator installs both tools on the host.**
The gate judges your worktree against *its* `requirements-gate.txt`, so once you
add the pins the host must already carry them, or every iteration is refused
with "worktree changed requirements-gate.txt: requirements-gate.txt is in
scope". That refusal would be the operator's environment, not your work.

## Goal

`requirements-gate.txt` pins `bandit==1.9.4` and `mutmut==3.8.0`. Both have a
`VERSION_PROBES` entry, so a stale copy first on PATH is caught the way it is
for ruff, and approve's "not found" message says PATH was looked at. Every
record and lock made after this names their versions in its `toolchain` block,
with no change to how that block is built.

## Required interface

The frozen tests read the real `requirements-gate.txt` and fake only
`gate._probe_versions(root, name)`.

- `requirements-gate.txt` gains two lines, `bandit==1.9.4` and
  `mutmut==3.8.0`, in the file's existing `name==version` form.
  `_pinned_versions(PROJECT_ROOT)` must return both pairs. Order is yours; after
  PyYAML reads best.
- `gate.VERSION_PROBES` gains `"bandit"` and `"mutmut"` keys. Each value is a
  shell command that contains the tool's name and `--version`. `bandit
  --version` prints `bandit 1.9.4` on its first line. `mutmut --version` comes
  from click's `version_option` and prints `mutmut, version 3.8.0`.
  `_VERSION_RE` already takes the first dotted number from either.
- **A bare `mutmut --version` does not work here, and the frozen test checks
  for this.** mutmut 3.8.0 loads its configuration at import time, even for
  `--version`. It exits 1 with `FileNotFoundError: Could not figure out where
  the code to mutate is` unless the working directory has one of these: a
  `src/` or `lib/` directory, a directory named after the checkout, or a
  `[tool.mutmut]` / `setup.cfg [mutmut]` setting. This repo has none of them,
  and `_probe_versions` runs probes with `cwd=root`. A naive probe would
  report nothing on PATH, the check would fall back to metadata alone, and a
  stale PATH copy would go unseen. The test runs the real `_probe_versions`
  against a stand-in `mutmut` on PATH. The stand-in fails unless the cwd has
  `src/` or `lib/`, and the test runs it from a checkout with neither, so
  the probe must give mutmut a directory it can guess from. A probe that
  `cd`s into a fresh `mktemp -d` holding an empty `src/`, runs `mutmut
  --version`, and removes the directory passed in the authoring probe.
  Do not add `[tool.mutmut]` to `pyproject.toml`: it is out of scope, and
  how mutmut is configured for real runs is T033's decision.
- Nothing else in `measure_toolchain`, `toolchain_problems` or `versions_of`
  needs to change. If you find yourself editing them, stop and re-read the
  tests.

The comment above `VERSION_PROBES` explains why ruff has an entry and a pure
library does not. Extend it in a line if bandit and mutmut need saying. They
are CLIs the panel shells out to, which is the same reason ruff has one.

## Out of scope

  requirements-gate.txt`.
