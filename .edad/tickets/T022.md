## Context

`check_freeze` in `edad/gate.py` proves the frozen tests and the ticket are what was
approved by hashing them against `.edad/hashes/<id>.json`. It reads that lock from the
tree it is verifying — the agent's worktree — and `.edad/` is in `INFRA_PREFIXES`, so
`changed_files` never reports it and `check_scope` never sees it. `check_scope` also
adds `frozen` to its allow-list on the theory that frozen files are checked by hash. So
an agent that edits a frozen test and rewrites its hash in the lock passes both checks;
demonstrated at HEAD in three lines. The lock's `_edad.ticket_sha256` and `red_proof`
are forgeable in the same edit. `evaluate` reads `requirements-gate.txt` from the same
tree: strip the pins and `measure_toolchain` returns `[]`, T020's mismatch refusal
never fires, and the record ships `toolchain: {}`.

`session.preflight` runs `check_freeze` against the main repo once, but its dirty-tree
check uses `changed_files`, which filters `.edad/` — so a re-approved lock that was
never committed is invisible, the worktree (cut from HEAD) holds the old lock, and the
gate judges against stale hashes. An existing bug, not a hypothetical.

The fix is additive because it has to be. T019's and T021's frozen suites fake
`check_freeze(root, ticket)`, `approval_meta(root, ticket_id)` and
`changed_files(root, base_ref)` by lambda on the `gate` module and call
`evaluate(tmp_path, TICKET)` with no `base_ref`. Those call shapes do not move. The
new check has a new name, runs only when `base_ref` is set, and proves the worktree's
copy equals base's *before* the existing readers read it.

One stand-in does reach it. T021's `Night` (`tests/test_gate_refusal.py`) drives the
real `run_session`, which passes a real `base_ref`, against an empty `wt/` with the
lock and ticket never written; the first run of this ticket (2026-09-14, `ddddc1d`)
passed acceptance and failed the full gate there — the freeze kill fired at iteration
1, ahead of the toolchain refusal the test is about. `Night` now fakes
`trusted_input_problems` alongside `check_freeze` (`raising=False`, so the suite is
green at this ticket's base too). A hand amendment before re-approval, not the
agent's; T021 is done and its lock's stale hash is left alone like T004–T006's.

Every acceptance test but one shells to git against a temporary repository (a real
base commit is what the tamper is compared to). Under `--sandbox docker` that fails
for the agent and passes for the verifier; an environment artifact, not the agent's to
work around. `tests/test_session_queue.py` and `tests/test_gate_mutation.py` behave
the same way.

Two tests in the frozen file are green at base and are not in `acceptance`:
`test_no_base_ref_makes_no_git_call_and_no_problem` and
`test_a_changed_pin_value_is_not_a_divergence`. They guard the implementation against
over-reaching — no `git show` without a base; a changed pin *value* is not a
divergence — and `full_gate` runs them. Keep them green.

## Goal

When `evaluate` has a base commit, the worktree's approval lock and ticket are
byte-identical to that commit's, and every tool the lock recorded as pinned at
approval is still pinned; a divergence reaches the record as a freeze failure naming
the file, and the session's existing `frozen_file_hash_mismatch` kill aborts on it.
`preflight` runs the same check against the main repo at HEAD and refuses before a
worktree exists. With no base there is no comparison and no `git show`; the record's
`base_ref: null` says so and QUICKSTART explains it. The printed harness line keeps
the commit `harness_of` preserves.

## Required interface

Pinned by `tests/test_gate_trusted_inputs.py`; read it first. Names and messages are
exact.

**`edad/gate.py`**

- `trusted_input_problems(root: Path, ticket_id: str, base_ref: str | None) -> list[str]`
  — beside `check_freeze`. Returns `[]` immediately when `base_ref` is `None`, running
  no git command. Otherwise, for each of `.edad/hashes/{ticket_id}.json` and
  `.edad/tickets/{ticket_id}.md`: the worktree file's bytes must equal
  `git show {base_ref}:<path>`; a file absent at base, or absent in the worktree, is a
  divergence. Then the pin floor: every key of `toolchain_of(approval_meta(root,
  ticket_id))` must be a name in `_pinned_versions(root)`; an absent block is vacuous.
  The docstring states the principle: every input the gate trusts is compared to base,
  and the list is enumerated here so a future input is added deliberately. Use the
  module's `git(root, ...)` helper (the no-base guard records calls to it); `git show`
  on a path absent at base raises `CalledProcessError` — catch it as "absent at base",
  never let it escape.
- Messages, verbatim (`{base}` is `base_ref` as passed; `{id}` the ticket id):
  - `approval lock modified since {base}: .edad/hashes/{id}.json (the harness's record of what was approved is not the agent's to edit)`
  - `ticket modified since {base}: .edad/tickets/{id}.md (re-approve to adopt the change)`
  - `pinned name dropped since approval: {name} (requirements-gate.txt at approval pinned it; removing a pin is a human commit before re-approval)`
- `evaluate`: after `rec.freeze_ok, freeze_problems = check_freeze(root, ticket)`,
  extend `freeze_problems` with `trusted_input_problems(root, ticket["id"], base_ref)`
  and set `rec.freeze_ok = False` when any were added, before
  `rec.violations += freeze_problems`. Nothing else in `evaluate` moves: a tampered run
  still runs no commands because `freeze_ok` is false, and the outcome is a `Record`,
  never a `die`.
- `harness_line`: when `source == "unknown"`, print `harness   unknown` followed by
  the short commit (`[:8]`) and `dirty` when the block carries them, in that order —
  the same pieces the known-source branch prints. T020's frozen test asserts only
  `"unknown" in` the line for the empty block, so `harness   unknown` alone stays
  correct there. `toolchain_line` is untouched.

**`edad/session.py`**

- Import `trusted_input_problems` from `.gate` in the existing import block.
- In `preflight`, after the lock-exists / `check_freeze` refusals and before
  `blocked_by`: `drift = trusted_input_problems(root, ticket["id"], "HEAD")`; if any,
  `raise Abort("contract drifted since HEAD; re-approve:\n  " + "\n  ".join(drift))`.
  The test asserts `str(exc.value).startswith("contract drifted since HEAD; re-approve:")`
  and that the lock path, ticket path or pinned name appears in the message.

**`QUICKSTART.md`**

- In `## Evidence`, one or two sentences: the record's `base_ref` is the commit the
  gate compared the worktree's lock, ticket and pin floor against; `null` means the
  gate was run by hand with no base and nothing was compared. The test requires the
  section to contain `base_ref`, `null`, and a word starting `compar`.

## Out of scope

- **Which copy of `edad/gate.py` judges the worktree.** The worktree contains the
  gate's own source; which copy runs is an import-resolution question, not a file-read
  one. Separate ticket after this one lands.
- **`edad/session_queue.py`.** It launches sessions by subprocess and inherits
  `preflight`.
- **The frozen T019/T021 files** (`tests/test_harness_identity.py`,
  `tests/test_gate_refusal.py`). Not in scope: the one amendment `Night` needed was
  made by hand before re-approval (see Context).
- **`toolchain_line`'s `unknown` for `{}`.** After this ticket a locked ticket cannot
  produce an empty toolchain block, so `unknown` stays accurate.
- **The pytest 9.0.3 bump.** It is the first ticket to put `requirements-gate.txt` in
  scope and depends on this one.
