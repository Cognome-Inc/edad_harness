## Context

T019 made every record and lock carry a `harness` block and a `toolchain` block. Two
things are not yet true of the toolchain block. `cmd_approve` probes every pinned name
twice — `gate_toolchain_problems` to refuse a mismatch, then `toolchain_versions` to
write the lock — and `evaluate` probes once and never checks: a hand-run
`python3 -m edad.gate run T0NN` on the wrong pytest writes a record naming the wrong
version and never says it was wrong. The `toolchain_versions` docstring claimed "the
same `_probe_versions` call" as the check; it was a second call. And nothing reads
either block: `report()` does not print them, and the artifacts on disk come in three
shapes — no key (T001–T018 and every lock before T019), `{}` (`.edad/evidence/T019.json`,
written by the harness before T019 through `Record`'s defaults), and the four-key block
— so each future reader re-derives the same normalisation and `{}` is the case it gets
wrong. `T019.json` is legitimately `{}` and must not be edited.

The stubs are already in `edad/gate.py`, beside `gate_toolchain_problems`, and they
return the wrong shape rather than raise, so every acceptance command fails on its own
assertion: `Measurement` is the bare dataclass, `measure_toolchain` and
`toolchain_problems` return `[]`, `versions_of`, `harness_of` and `toolchain_of` return
`{}`. The frozen file was amended before approval: the two T019 record-and-lock tests
now steer the toolchain by faking `measure_toolchain` with a list of `Measurement`s, the
one module-level name both `evaluate` and `cmd_approve` must read, and fail at base
because neither caller calls it yet. `test_toolchain_versions_stores_what_the_pin_check_measures`
(T019's D3) is green at base and stays green: only its docstring changed, and it is
what keeps the two wrappers honest through the rewrite. It is run by `full_gate`, not
by `acceptance`.

Two things the suite does that are not yours to fix. `tests/test_session_queue.py`
runs `git` against real temporary repositories and `test_run_log_is_gitignored_telemetry`
shells to `git check-ignore`; under `--sandbox docker` git does not work inside the
container, by design, so those tests fail when you run the full suite yourself and
pass for the verifier, which runs on the host. That failure is an environment
artifact, not yours, and not to be worked around. Nothing in `acceptance` shells to
git. And `tests/test_gate_red_proof.py` still fakes `gate_toolchain_problems` in one
approve test; that fake becomes inert after this change and the test passes anyway,
because its `tmp_path` has no pins file. The file is out of scope; leave it.

## Goal

The toolchain is measured once per command. One pass over `requirements-gate.txt` and
one probe per pinned name give a list of measurements; the pin check and the versions
a record stores are two pure readings of that list. `evaluate` reads the check too: on
a mismatch it dies with `cmd_approve`'s message before any command runs and before a
`Record` exists, so a record's `toolchain` block means "these pins were satisfied when
this verdict was made". Two pure readers turn the `harness` and `toolchain` blocks of
any artifact — absent, `{}`, partial or full — into one shape without touching the
disk. `report()` prints both through the readers; `cmd_approve` prints the harness
line after the frozen-file hashes; the quickstart names the fields where it describes
the record. `gate_toolchain_problems(root)` and `toolchain_versions(root)` remain,
as one-line wrappers, so `session.preflight` and T019's test are untouched.

## Required interface

All of it is pinned by `tests/test_harness_identity.py`; read it first, from the
`toolchain-measurement` banner down, and the two amended D4 tests above it. Names are
exact: the tests reach every one as `gate.<name>` and monkeypatch `measure_toolchain`
and `_probe_versions` on the `edad.gate` module.

**`edad/gate.py`** — replace the six stubs beside `gate_toolchain_problems`.

- `Measurement(name, pinned, meta, on_path)` — the dataclass as stubbed; the tests
  construct it positionally in that order and read those four attributes. Whether
  `measured` (`meta or on_path`) is a property or a helper is yours.
- `measure_toolchain(root: Path) -> list[Measurement]` — one `_pinned_versions(root)`
  pass and exactly one `_probe_versions(root, name)` call per pinned name, in file
  order; `[]` when the pins file is absent, without probing. The test counts probe
  calls and checks their order.
- `toolchain_problems(measurements) -> list[str]` — the body of today's
  `gate_toolchain_problems`, reading `Measurement`s instead of probing. Its three
  messages are unchanged, word for word: the test asserts
  `"ruff: not found"` and `"pytest: 0.0.9, pinned 0.0.1"` as substrings.
- `versions_of(measurements) -> dict` — `{m.name: m.meta or m.on_path}`, in order.
- `gate_toolchain_problems(root)` → `toolchain_problems(measure_toolchain(root))`;
  `toolchain_versions(root)` → `versions_of(measure_toolchain(root))`. Fix the
  latter's docstring: it now takes its own measurement.
- `harness_of(artifact: dict) -> dict` — returns exactly the keys `version`, `commit`,
  `dirty`, `source`, in that order. `artifact.get("harness")` absent, `{}`, `None` or
  any non-dict → all `None` with `source: "unknown"`. A dict → `.get` each of the four
  keys, so extra keys are dropped and missing ones are `None`, and a missing or falsy
  `source` becomes `"unknown"` while the other values are kept — a block with a
  commit and no `source` keeps the commit. Never raises; never mutates the argument.
- `toolchain_of(artifact: dict) -> dict` — a copy of `artifact.get("toolchain")` if
  it is a dict, else `{}`. Never raises; never mutates.
- `evaluate()`: after the "no commands" check and before `rec = Record(...)`, call
  `measure_toolchain(root)` once; if `toolchain_problems(...)` is non-empty, `die()`
  with the same message `cmd_approve` uses today (extract it into a shared helper
  rather than duplicating the string — the test asserts
  `"does not match requirements-gate.txt"` in stderr and `SystemExit` code 2).
  Neither `harness_identity()` nor `run_commands` may be reached on a mismatch: the
  test replaces both with a function that raises. Build the record with
  `toolchain=versions_of(measurements)` from that same list; `toolchain_versions` is
  no longer called here.
- `cmd_approve()`: call `measure_toolchain(root)` exactly once, before the existing
  conditional check; the check reads `toolchain_problems` of it and the lock's
  `"toolchain"` reads `versions_of` of it. `gate_toolchain_problems` and
  `toolchain_versions` are no longer called here. After the loop that prints each
  frozen-file hash, print one line beginning `  harness   ` with the same text
  `report()` prints, from `harness_of(lock["_edad"])`.
- `report()`: immediately after the `decisions` line (and whether or not there is
  one), print two lines. The test finds each as the single stripped line starting with
  `harness` / `toolchain`, so nothing else `report()` prints may start with those
  words. Harness line: `harness   <source> <commit[:8]>[ dirty][ v<version>]` — the
  `dirty` token only when `dirty` is true, the `v<version>` token only when there is a
  version; `harness   unknown` when `source` is unknown. Toolchain line:
  `toolchain <name> <ver>, <name> <ver>` in the block's order, `unknown` for a
  `None` version, and `toolchain unknown` when the block is empty. Both go through
  `harness_of`/`toolchain_of` over the record's fields, so a record with `{}` in
  either prints `unknown` rather than raising. Exact spacing beyond the leading
  label is yours; the test asserts substrings.
- `harness_dirty`: add a comment saying why `--untracked-files=no` — an untracked
  file changes behaviour only if something imports it; counting untracked files is a
  deferred decision. (D9; unenforced — a comment.)
