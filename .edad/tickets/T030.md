## Context

Everything in the review loops that launches a model lives in a new module,
`edad/review.py`, kept out of the gate (D17). This ticket creates that module's
skeleton and its two pure seams. Later tickets fill in the behaviour.

- **S3, the CLI parser.** `build_parser()` is built apart from `main()`, the way
  `edad.session` and `edad.session_queue` already do it. It has `tests <T>` and
  `panel <T>` subcommands, each routed to a handler. T031 fills the `tests`
  handler. T036 fills the `panel` one.
- **S4, the command and prompt builders.** These are pure, in the style of
  `agent_argv` (`edad/session.py:777`). The reviewer is always a brand-new
  `claude -p` process: never `--resume`, `--continue`, `-r` or `-c` (D5). Its
  prompt is the spec, the artifact under review and every item of its rubric,
  and nothing else. It gets no conversation and no ticket-writing rationale.

The rubrics are the grill record's checklists, verbatim
(`.edad/grills/review-loops.md`, under D18 and D19):

- T1–T8 go in `edad/rubrics/tests.md`.
- C1–C6 go in `edad/rubrics/code.md`.
- S1–S6 go in `edad/rubrics/security.md`.

**Narrowed decision.** D17's line says the panel "is called by the night run".
D21 narrows that: the panel runs inside the session, and `edad.review panel
<T>` is only a manual re-run on a worktree left behind.

**Model pin is T034's.** D15 (`--model claude-opus-5-5`, overridable by
`EDAD_REVIEW_MODEL`) is proven in T034. This ticket's argv test asserts
properties, not argv equality, so adding the model flag later does not break
it.

**`pyproject.toml` is not in the spec's scope. It was added here.** The harness
is pip-installed into targets (`pip install git+…@v0.1.1`), and `[tool.setuptools]
packages = ["edad"]` ships `.py` files only. A rubric file that is not package
data is absent from every non-editable install, so the reviewer's prompt would
fail on ai-sniffer and nowhere in this repo. The fix is a
`[tool.setuptools.package-data]` entry for `edad/rubrics/*.md`. Whether a frozen
test pins it was settled at authoring: yes, by
`test_rubric_files_ship_as_package_data`. A wheel built from the authoring probe
was checked by hand and carried all three rubric files.

## Goal

`python3 -m edad.review --help` lists `tests` and `panel`. The reviewer command
builder returns a fresh `claude -p` argv. The prompt builder returns a prompt
that holds the spec, the artifact and every rubric item, and nothing else. The
three rubric files exist with the grill's items.

## Required interface

`edad/review.py` lands as importable, returning stubs. Every name below exists,
so each frozen test goes red on its assertion. Replace the bodies; keep the
names and signatures.

- `build_parser() -> argparse.ArgumentParser` with `prog="edad.review"`, and
  required subcommands `tests` and `panel`. Each takes one positional `ticket` and
  routes to its handler with `set_defaults(func=cmd_tests)` /
  `set_defaults(func=cmd_panel)`. The subparsers are `required=True`, so a bare
  `python3 -m edad.review` is argparse's usage error (exit 2) rather than an
  `AttributeError` on `args.func`. Copy `edad.session.build_parser`.
- `main() -> int` parses `sys.argv` (no argv parameter, as in `edad.session`)
  and returns `args.func(args)`. The test replaces `cmd_tests` and `cmd_panel`
  on the module, so `main` must reach them through `build_parser()` at call
  time, not through a parser built at import.
- `cmd_tests(args)` and `cmd_panel(args)` are placeholders here. Each prints
  to stderr that it is not built yet, naming T031 or T036, and returns 2.
  Nothing in them spawns a process.
- `review_prompt(spec: str, artifact: str, rubric: str) -> str`. The test
  pins these three parameters as the first three, in this order. A later ticket
  may add an input only as a keyword-only parameter with a default (T031's
  disputes, T034's bandit output); do not add one here. The result must contain
  each of the three strings verbatim. It must depend on nothing but its
  arguments: it does not read files, the cwd or the environment. Framing around
  them is yours, at most 600 characters. Exact wording is deferred to real
  reviews. **Do not open the prompt with the spec.** A spec starts with `---`
  front matter, and an argv element starting with `-` would be read as a
  flag. Put the instruction first.
- `reviewer_argv(prompt: str) -> list[str]` starts `["claude", "-p"]` and
  carries `prompt` as exactly one element. It has no `--resume`, `-r`,
  `--continue` or `-c`. It does not read `EDAD_AGENT_CMD`, because that
  override is the coding agent's; the test sets it to a `--continue` command.
  Do not add `--model`; that is T034's.
- `load_rubric(name: str) -> str` returns the text of
  `edad/rubrics/<name>.md` and only that file. Read it through
  `importlib.resources`, not a path relative to the cwd: the test calls it from a
  temp directory. A prompt built from one rubric must carry no other rubric's
  ids (`T1`-`T8`, `C1`-`C6`, `S1`-`S6`).
- Each rubric file holds its grill items verbatim. Copy the grill's code blocks
  under D18 and D19 (`.edad/grills/review-loops.md`); `security.md` also says
  bandit's output is attached. The test looks for each item's id and label
  (`T3 ONE THING`, `C4 fits the codebase`, `S4 unsafe deserialization`), so
  keep each id and its label on one line with a single space between them.
- `pyproject.toml` gains `[tool.setuptools.package-data]` with
  `edad = ["rubrics/*.md"]`. Change nothing else in that file. The test globs
  the patterns from `edad/` the way setuptools does, so `"*.md"` or `"*"` do
  not count: they ship nothing under `rubrics/`.
