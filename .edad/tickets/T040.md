## Context

T031 added `--tools ""` to the reviewer's argv, and its docstring says "the
prompt is all it can read". That is not true. `--tools ""` switches tools off,
but it does not stop the context `claude` loads at startup. `run_reviewer`
passes no `cwd`, so the reviewer starts wherever `edad.review tests` was run,
which is the repo root.

A real probe (2026-10-28, `claude` 2.1.280) started in the repo root quoted
this project's memory index, named the branch and described T031's night. The
same probe from a fresh empty temp directory saw none of that. Adding a fixed
`--system-prompt` also removed Claude Code's coding-assistant framing: memory
instructions, environment sections and slash commands. What remains either way
is the account email, the username in paths, the platform, the date and the
model id. `claude` injects these regardless, and none is about the ticket
(D30).

**Rejected:**
- `--bare`: it authenticates only by API key, and the daytime review runs on
  the operator's OAuth login.
- An empty directory alone: it keeps the coding-assistant framing.

**How the tests reach it.** There are two seams, both named in the spec:

- **Seam S5.** The empty-directory test drives `review.main()` with only
  `subprocess.run` faked, so the real `run_reviewer` runs. The fake records
  what it was given while the call is in progress:
  - `cwd` exists and is empty;
  - it is outside the repo;
  - no directory from it up to `/` holds a `.git` or a `CLAUDE.md`;
  - and, checked after the call, the directory is gone.
- **Seam S4.** The argv test calls `reviewer_argv` directly.

Neither test launches a model, and neither shells to git.

**The live canary (D31): hand-run, not acceptance.** The file
`live_tests/test_reviewer_isolation.py` is frozen with this contract. It is
modelled on `docker_tests/`: it sits outside `testpaths` and refuses to import
without `EDAD_LIVE_REVIEW=1`. It builds a temp git project with a made-up word
in its CLAUDE.md and its branch name, enters it, and holds two tests:

- **The control.** Plain `claude -p --tools ""` started there repeats the
  word. This proves `claude` still loads that context, so the next test
  cannot pass on nothing.
- **The isolation test.** The real `review.run_reviewer(review.reviewer_argv(...))`
  does not repeat the word.

It needs the network, which the night's sandbox denies, so it is not an
acceptance command. Run it by hand at approval and after any `claude` upgrade:

    EDAD_LIVE_REVIEW=1 python3 -m pytest live_tests/test_reviewer_isolation.py -q

The file shells to `git`, but no gate command collects it.

## Goal

The test reviewer starts in a fresh empty directory outside any project, with
a fixed role in place of Claude Code's default system prompt. Started from the
repo, it can no longer see the project's CLAUDE.md, git status or memory.

## Required interface

- **`run_reviewer(argv: list[str]) -> str`** keeps its one-argument
  signature. T031's frozen `Reviewer` stand-in replaces it with a
  one-argument callable. It creates the directory itself with
  `tempfile.TemporaryDirectory()` (in the system temp location, never inside
  the repo), passes it to `subprocess.run` as `cwd=`, and lets it be deleted
  when the process exits. Everything else is unchanged: `capture_output=True,
  text=True`, the stdout returned, and a non-zero exit refused through
  `gate.die()` with no round recorded.
- **`reviewer_argv(prompt: str) -> list[str]`** adds `--system-prompt <fixed
  text>`, exactly once and as two tokens. The text must:
  - be the same for every prompt, non-empty and at most 300 characters;
  - contain the word "review";
  - carry nothing from the spec, artifact or rubric.

  Never use `--append-system-prompt`, which keeps the default. T030's argv
  test still holds: `claude -p` comes first, the prompt appears once, and
  there is no resume flag. `--tools ""` stays.
- **Docstrings.** Correct T031's "the prompt is all it can read". The
  reviewer still sees what `claude` injects regardless: account email,
  username, platform, date and model id.

The exact wording, constant names and temp-dir prefix are yours to choose.
