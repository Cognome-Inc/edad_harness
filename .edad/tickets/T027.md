## Context

This harness develops itself, so every agent worktree carries a full copy of
`edad/` — including `gate.py`, the module that judges it — and tickets such as
T026 edit that very file. Two copies are in play on every night. The **judge** is
the copy the controller process imported: the night runs `python3 -m
edad.session` with the main checkout as its working directory, imports `edad`
once, and calls `evaluate()` in-process, so the judge is the main checkout's copy
for the whole session (the installed harness, for any other target). The
**subject** is the worktree, and the commands the gate runs in it —
`run_commands` uses `cwd=root` — import the worktree's own copy, because the
working directory wins on `sys.path`. The evidence record already names both:
`harness.commit` is derived from where the judging module lives (`harness_checkout`
reads `edad.__file__`), `commit` is the worktree's HEAD.

Nothing pinned either half until the frozen file, and one path collapses them:
`cd <worktree>; python3 -m edad.gate run T` imports the worktree's `edad/gate.py`
and judges the worktree with it — the subject grading itself — and prints the
same `harness checkout` line a main-checkout run would. Nothing refuses. It is an
operator path today (the container has no git and never runs the gate), but it
is the same class of silent-wrong verdict that T026 closed for base refs, and a
future change that shelled the gate out from the worktree would open it for
every night with nothing to catch it.

**Your container has no git.** Five of the six tests in the frozen file build a
real temporary repository and add a linked worktree of it (`git worktree add`),
and one spawns `python3 -m edad.gate` from inside that worktree. All five fail
where you run them; the verifier on the host runs them for real. Only the
QUICKSTART text test runs for you. Do not work around this. Confirm your change
by reading the frozen file and reasoning about it, and by running the rest of
the suite, which does pass in-container apart from the tests elsewhere that also
shell to git.

**Two tests in the frozen file are already green** and are not in `acceptance`:
`test_a_sabotaged_worktree_copy_of_the_gate_is_never_consulted` (D1 — the real
`evaluate` on a worktree whose own `gate.py` has been neutered still reports the
edited frozen file, and the neutered copy is never imported) and
`test_commands_run_in_the_worktree_import_the_worktree_copy` (D3 — a command run
through `run_commands(wt, ...)` resolves `import edad` to the worktree's copy,
even with `PYTHONPATH` pointing at the main checkout). They hold today because
the judge is already in-process and the working directory already wins; they
stay in the file under `full_gate` so that neither can be lost silently. Keep
them green: do not touch `run_commands`, and do not set or scrub `PYTHONPATH`
anywhere.

## Goal

When `evaluate` is asked to judge a tree, the first thing it checks — before the
base-ref probe, before the toolchain is measured, before any `Record` is built —
is whether the gate module it is running from lives inside that very tree *and*
the tree is a linked worktree. If so, it refuses through `die()`, naming the
tree. The main checkout judging itself is not that case and stays allowed: that
is approve time and every hand-run so far. QUICKSTART tells the operator which
copy judges, that the record names both, that a queue night's judge is the run
branch's tip at each spawn, and that a hand-run from inside a worktree is
refused. `evaluate`'s docstring states the same rule.

## Required interface

The frozen tests assert these; neither side can change them.

**`evaluate(root, ticket, gate_name="acceptance", base_ref=None)`** — unchanged
signature. The guard's condition is exactly: `harness_checkout()` is not `None`,
equals `root.resolve()`, and `(root / ".git").is_file()`. All three must hold to
refuse; a `.git` *directory* at `root` is the main checkout and is never refused,
and a `harness_checkout()` of `None` (an install with no `.git` above it) is
never refused. It needs no git and no measurement — a path comparison only — and
runs ahead of `die_on_bad_base_ref` and `measure_toolchain`: with a bad
`base_ref` and a mismatched toolchain both present, the reason names the
worktree and mentions neither the ref nor the pins (D2, third test).

**The refusal is `die(...)`** — the existing helper: `edad: <reason>` on stderr,
`gate.Refusal` raised (a `SystemExit` with `code == 2` and `.reason`), no
traceback. The reason must contain the tree's path — `str(root)` or
`str(root.resolve())`, either spelling passes. Wording is otherwise yours.

**`harness_checkout` is looked up at call time as a module attribute** — call
`harness_checkout()` by its module-level name inside `evaluate`, exactly as
`harness_identity` already does, so that the frozen tests can replace
`gate.harness_checkout` the way T019's tests do. Do not cache it at import time
and do not read `edad.__file__` directly in the guard.

**The CLI** `python3 -m edad.gate run <ticket>`, spawned with the worktree as
its working directory and no `PYTHONPATH`, exits 2 with `edad: ` and the
worktree's path on stderr and no `Traceback` on either stream. That is `die()`'s
existing behaviour once the refusal is raised; nothing in `cmd_run` or `main`
needs to change. The child imports the worktree's copy of `edad/` — the frozen
test commits a copy of the package into its temporary repository for exactly
this — so the guard has to be in `gate.py` itself, not in the controller.

**QUICKSTART** gains a section whose heading is exactly `## Which copy judges`
(a level-two heading, that text, nothing after it on the line). The section
must contain the word `worktree` and a word beginning `refus` (refused,
refuses, refusal). Say, in the operator's terms: the judge is the copy the
controller imported and the subject is the worktree, whose commands import
their own copy; the record names both (`harness.commit` and `commit`); in a
queue night the judge is the run branch's tip at each child's spawn, so a
promoted `gate.py` change judges the tickets after it; and a hand-run from
inside a worktree is refused, with why. Put it after `## Evidence` and before
`## Releasing`, or wherever it reads best — the test finds it by heading.

**`evaluate`'s docstring** states the same rule in a sentence or two. No test
pins the docstring; the spec asks for it.
